# edit-guard（ファイル編集のフック）

`plugin/hooks/edit_guard.py` は、Claude Code の Bash の呼び出しの前に動くフック（PreToolUse）。エージェントが確かめずにファイルを書き換えるコマンドを止め、代わりに何を使うかを返す。rpatch で部分の書き換えを確かめられるようにしても、ほかの書き込みの経路が残っていたので、それをふさぐ。

## 止めるもの

| 規則 | 止めるコマンド | 理由 |
|---|---|---|
| `python-replace` | python の `.replace(` や `re.sub(` で、ファイルに書き戻すもの（`python3 -I -`・`-Ic` のようにインタープリタの引数が付いた形も） | 文字列が見つからなくても黙って何もしない |
| `sed-in-place` | git が追跡しているファイルへの `sed -i`・`perl -i` | 同じく、パターンが当たらなくても黙って成功する |
| `overwrite-tracked` | git が追跡しているファイルを `cat`・`echo`・`printf` の `>`（`&>`・`>&` も）や、`-a` のない `tee` で丸ごと置き換えるもの | いまの中身を確かめずに全部を置き換える |

止めたときの理由は `Blocked by a hook:` で始まり、`[edit-guard: 規則の名前]` で終わる。代わりの手は、部分の書き換えなら rpatch、丸ごとの書き直しなら Write ツール（読んでいるかを確かめてくれる）か `>|`。

通すもの: 新しいファイル、git が追跡していないファイル（エージェントが自分で作った下書きなど）、一時ディレクトリ（`$TMPDIR`、`/tmp`、`/var/folders`）、追記（`>>`）、`>|`（丸ごと書き直すと明示したもの）、どのファイルに書くのか分からないもの（変数、グロブ、追えない `cd` のあと）。フックの中で何かが失敗したときもコマンドを通す。`RPATCH_GUARD=off` を Claude Code を起動する環境に入れると、全体を切れる。

## 判定の仕方

コマンドの文字列を小さなシェルの字句解析（`Lexer`）で読み、コマンドごとに「作業ディレクトリ・名前・引数・リダイレクト」（`Command`）にしてから、規則がそれを見る。

- 引用（行をまたぐものも）、バックスラッシュと行の継続、コメント、`$( )` とバッククォート（入れ子のコマンドとして読む）を扱う。heredoc は、区切りがどの形でも（`<<'EOF'`、`<<\EOF`、`<<123`）、どこにあっても（`"$(cat <<'EOF' … )"` の中でも）本文を飛ばす。
- `cd` は、そのサブシェルの終わりまで効く。パイプの中やバックグラウンドの `cd` は後ろに効かない。`popd`、`cd -`、存在しないディレクトリへの `cd` のあとは、作業ディレクトリを「不明」にして、止めない。
- `if`・`{` などの予約語と、`sudo`・`env`・`timeout` などのラッパー（とその引数）を飛ばして、本当のコマンドの名前を探す。
- 「git が追跡しているか」は、実パスで `git ls-files --error-unmatch` に聞く。

python の規則だけは、初代のフックと同じ判定にするため、解析より前に生の文字列で判定する。

## 確かめ方

- 単体テスト: `python3 -m unittest discover -s tools/hooks`。別のモデルにこのフックの回避を試させて出た、止めるべきもの・通すべきものの例を全部入れてある。
- 当て直し: 過去の Bash のコマンドを JSONL に書き出し（セッションの中身を含むので、リポジトリの外に置いて終わったら消す）、`python3 tools/hooks/replay.py <file> --samples 5`。規則ごとの件数、初代のフックとの一致、最も遅かったコマンドを出す。初代のフックとの一致は、`--old` で旧版のフックのファイルを渡したときだけ出る。

- 引用していない `rpatch <<EOF` の heredoc を止める規則は、わざと変数を展開する正当な使い方があるので置かない。

## 入れ方

- 設定ファイルに書く: `~/.claude/settings.json` の `hooks.PreToolUse` に、次の項目を足す（`/絶対パス/` は、このリポジトリを置いた場所）。リポジトリのファイルを直せば、そのまま効く。

  ```json
  {
    "hooks": {
      "PreToolUse": [
        {
          "matcher": "Bash",
          "hooks": [
            {
              "type": "command",
              "command": "python3 /絶対パス/rpatch/plugin/hooks/edit_guard.py",
              "timeout": 10
            }
          ]
        }
      ]
    }
  }
  ```

- 配る形は `plugin/`（Claude Code のプラグイン。マニフェスト、`hooks/hooks.json`、rpatch のスキル）。`claude plugin validate plugin` で確かめられる。試すときは `claude --plugin-dir plugin`。settings.json のフックと両方を有効にすると、フックが 2 回走る（判定は同じ）。プラグインの版は Cargo.toml と同じにする（単体テストで確かめる）。
- 集計: `tools/log-analysis/session.py` とダッシュボードは、止められた呼び出しを `阻止` として数え、規則ごとの件数と、止まったあと何で書いたかを出す。metrics.py は `hook_blocked` に規則ごとの件数を出す。

## 範囲の外

- Codex 向けのフックは無い。
- `jq . f > f` のような、プログラムの出力での上書きは止めない（生成物を書く正当な使い方と区別できないため）。止めるのは、エージェントが中身を書く `cat`・`echo`・`printf`・`tee` だけ。
- まとまりへのリダイレクト（`{ echo a; } > f`、`( echo a ) > f`、`if …; fi > f`）は止めない。リダイレクトはまとまりの閉じのあとにあり、中のコマンドには付かないため。
- `pushd` のあとの `popd` で元の場所に戻る場合など、作業ディレクトリが分からなくなったあとの書き込みは見逃す（止めすぎないほうを選んだ）。
- Write ツールは見ていない（フックは Bash だけ）。Write は既存のファイルを書く前に、読んだことと読んだあとに変わっていないことを確かめるので、丸ごとの書き直しの逃げ先にしている。
