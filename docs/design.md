# rpatch の設計

rpatch は、既存の UTF-8 ファイルを完全一致でまとめて編集する CLI。エージェントが Bash から呼ぶことを前提にしている。方針は 4 つ。

- 一致は完全一致だけ。空白や改行の違いを曖昧に許さない。
- 全部か無しか。1 つでも当たらない編集があれば、どのファイルにも書き込まない。
- 失敗したときは、行番号と原因を示して、次の 1 回で直せるようにする。
- 入力はエスケープなしで書ける（区切り形式）。

使い方は `rpatch --help`。MCP サーバーは [mcp.md](mcp.md)。英語版は [design.en.md](design.en.md)、LLM 向けの短い入口は [llms.txt](../llms.txt)。

## 処理の流れ

`lib.rs` の `apply()` が、CLI と MCP の両方から呼ばれる。1 回の呼び出しは次の順に進む。

1. **解析**（`input.rs`、`block.rs`）
   - 入力の先頭（空白を除く）が `{` なら JSON、それ以外は区切り形式として読む。
   - どちらも `Edit` の列にしてから、まとめて検査する（`input::validate`）。空の OLD、`old == new`、2 行以上の BEFORE/AFTER、空の挿入、`count=0` は入力の誤り（終了コード 2）。
2. **読み込み**（`lib.rs` の `load_files`）
   - 編集に出てくるファイルを 1 回ずつ読む。パスは `cwd` を基準に `canonicalize` し、書き方の違う同じファイル（`a.txt` と `./a.txt`、symlink とリンク先）を 1 つにまとめる。symlink はリンク先を編集する。
   - UTF-8 でなければ読み込みの失敗（終了コード 3）。先頭の BOM は外して覚えておき、照合には使わない。
   - 権限とハードリンクの数も覚えておく。
3. **照合と適用**（`matcher.rs`、`lib.rs` の `apply_edits`）
   - 編集を入力の順に、そのファイルの「いまの内容」に当てる。同じファイルへの後の編集は、前の編集の結果を見る。
   - 当たらなかったら、そのファイルの残りの編集は照合しない（「not checked」と表示）。ほかのファイルの編集は照合を続ける。
   - 当たらなかった編集が、同じ一括の前の編集を当てる前の内容なら当たる場合は、そのことも示す（前の編集が文字列を変えてしまった、というよくある間違い）。
4. **書き込み**（`write.rs`）
   - 当たらなかった編集が 1 つでもあれば、何も書かずに終わる。`--dry-run` でも書かない。
   - 先に、書き換えるファイルに読み取り専用のものがないかを確かめる（rename だと読み取り専用でも書けてしまうため）。
   - ファイルごとに、同じディレクトリの一時ファイル（`.rpatch-*`）に書き、`fsync` し、元の権限を付けてから rename で置き換える。BOM があったファイルには付け直す。
   - 途中のファイルで書き込みに失敗したら、それまでに書いたファイルを元の内容に戻す。戻すのにも失敗したら、変更が残ったファイルを報告する。
5. **出力**
   - ファイルごとに `M <file>  edits=<n>  at_lines=<変わった行>` を出す。範囲置換は置き換えた行の範囲を、ハードリンクのあるファイルは警告を、その下に出す。
   - `--diff` なら unified diff を付ける。見出しは `a/<file>` と `b/<file>`。絶対パスはそのまま出す。

rename で置き換えるので、ハードリンクは切れる（ほかのリンクは古い内容のまま）。そのときは警告を出す。ほかのプロセスとの同時編集や、プロセスが途中で止まった場合の巻き戻しは扱わない。

## モジュール

| ファイル | 役割 |
|---|---|
| `main.rs` | 引数の処理、stdin の読み込み、終了コード。`rpatch mcp` を MCP サーバーへ回す |
| `lib.rs` | `apply()`。読み込み、編集の適用、`at_lines` の計算、出力の組み立て |
| `input.rs` | 入力の判別、JSON の解析、`Edit` と `Target` の定義、入力の検査 |
| `block.rs` | 区切り形式の解析と、区切りの書き間違いの診断 |
| `matcher.rs` | 1 つの編集がファイルのどこに当たるかを探す。当たらないときの診断の入口 |
| `diagnose.rs` | 見つからない・数が合わないときの説明（似ている行など） |
| `write.rs` | 全部か無しかの書き込みと、失敗したときの巻き戻し |
| `text.rs` | 行番号の計算と、診断での行の表示 |
| `mcp.rs` | MCP サーバー（Cargo feature `mcp` のときだけ） |
| `help.txt` | `--help` の本文 |

## 編集の種類

`Edit` は、対象（`Target`）、置き換える文字列（`new`）、一致すべき回数（`count`）を持つ。区切り形式から作った編集は `lines = true`、そのうち `OLD part` は `part = true` も立つ。

| 書き方 | `Target` | 照合 |
|---|---|---|
| `<<<<<<< OLD` | `Text` | 行の先頭からだけ。行全体 |
| `<<<<<<< OLD part` | `Text`（`part`） | どこでも。最後の改行は含めない |
| `<<<<<<< FROM` / `TO` | `Range` | 行の先頭からだけ。最後の行は行の先頭部分でよい |
| `<<<<<<< BEFORE` / `AFTER` | `Insert` | どこでも（1 行の一部）。行の境目に挿入する |
| JSON の `old` | `Text` | どこでも |
| JSON の `from` / `to` | `Range` | どこでも |

### 共通の規則

- 一致は重なり合うものも数える（`x\nx\nx` に `x\nx` は 2 回）。重なっていたら `count` に関係なく失敗にする。重なりを数えないと、曖昧な文字列が黙って最初の一致に当たってしまう。
- 一致の数は `count`（既定 1）とちょうど同じでなければ失敗。

### 区切り形式の改行

- ブロックの各行は改行で終わるものとして扱う。ファイルが CRLF なら、ブロックの改行も CRLF に合わせてから照合する。JSON の文字列は変換しない。
- ファイルの最終行に改行がないとき、OLD はその行に改行なしで一致させ、置き換えたあともファイルの末尾に改行を足さない（`last_line_match`）。AFTER で最終行の後ろに挿入するときも同じ。

### OLD と OLD part

- OLD は行全体だけに一致する。長い行の先頭だけを書いたつもりで部分一致させると、行の残りが黙って残るので、行の一部としてだけ見つかったときは失敗にして、その行を示す。
- 行の一部を書き換えたいときは `OLD part` と明示する。中身はどこにでも一致し、最後の改行は含めない（JSON の `old` と同じ）。

### FROM / TO

- FROM はちょうど 1 回一致しなければならない。TO は FROM の最後の行より後ろで、最初に一致したもの。
- FROM から TO の手前までを NEW で置き換え、TO は残す。NEW の末尾が TO と同じなら失敗にする（TO が 2 回並ぶ、よくある間違い）。
- TO が空なら、FROM からファイルの最後までを置き換える。ファイルの末尾を消すのに、エージェントが `head -n` で行番号を使って切っていたため（2026-10-02）。

### BEFORE / AFTER

- アンカーは 1 行（またはその一部）で、ちょうど `count` 回一致しなければならない。同じ行で 2 回一致したら失敗。
- 既存の行は書き換えず、アンカーを含む行の前後の境目に NEW の行を挿入する。同じアンカーへの AFTER を重ねると、後の AFTER ほどアンカーの直後に入るので、順番が逆になる。

## 診断

当たらなかった編集には、見出しと説明を付ける。

- **見つからない**
  - 区切り形式で、行の一部としてだけ見つかるなら、どの行のどこ（先頭だけ・末尾だけ・途中）かを示し、`OLD part` や BEFORE/AFTER を案内する（`matcher.rs` の `partial_line`）。
  - それ以外は、次の順で最初に当てはまったものを 1 つ出す（`diagnose::not_found`）: CRLF の違い → 空白の違い（該当行）→ どこまで一致してどこで食い違うか → 一番似ている行。
- **数が合わない**: 一致した行の一覧（10 か所まで）と、`count` の書き方のヒント。
- **重なり**: 重なった範囲（同じ行の中なら列）と、前後を足すヒント。
- **入力の誤り**: JSON の構文エラーは該当箇所の前後とキャレット、`\'` や生の改行についてのヒント。区切り形式は、区切りの長さの違いや閉じ忘れのヒント、自己流の形式（`--- old` など）には正しい書き方の例。

行の表示は 200 文字で切る。ただし「行の一部としてだけ見つかった」ときの行は、そのままコピーして使えるよう 4000 文字まで出す。

## at_lines

各ファイルについて、編集で変わったバイト範囲（`changes`）を覚えておく。後の編集で内容がずれたら、範囲も付け替える（`splice`）。

- 置き換えた文字列と新しい文字列で、先頭と末尾が同じ行は数えない（文脈として書いた行）。
- 削除は、消えた位置にいまある行を示す。ファイルの末尾を消したときは最終行。
- 範囲は行番号に直して並べ、隣り合うものをまとめる（`3,10-12`）。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | すべて当たった（`--dry-run` を含む） |
| 1 | 当たらない編集があった、またはファイルがない |
| 2 | 入力の誤り（解析できない、空の OLD、`old == new` など）、引数の誤り |
| 3 | 読み書きの失敗（UTF-8 でない、読み取り専用、一時ファイルや rename の失敗）|

## 範囲外にしたもの

- 新しいファイルの作成と、ファイルの削除（`cat > file <<'EOF'` や `rm` で足りる）。
- 正規表現での置換（`sd` がある）。
- 書き込む前の構文チェック。実際に壊した編集は 670 回中 3 回（0.45%）で、エージェント自身の確認ですぐ見つかっていたので見送った。

## テスト

- `tests/cli.rs`: CLI の結合テスト。編集の種類ごとの成功と失敗、診断の文面、書き込みの性質（権限、symlink、BOM、ハードリンク、読み取り専用）を見る。
- 各モジュールの単体テスト（行番号の計算、重なりを含む一致の列挙など）。
- `tests/mcp.rs`: MCP サーバーの接続と、CLI と同じ出力になること（`--features mcp` のときだけ）。

`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test` を、feature なしと `--features mcp` の両方で通す。CI（`.github/workflows/build.yml`）は手動で起動する。
