# rpatch v0.5.0 の確認メモ

2026-10-01、`~/project/prod/beat-jam` のセッション（Claude Code、Opus）。対象は 590677f（`rpatch -V` で 0.5.0、`~/.cargo/bin/rpatch`）。v0.4.1 のメモ（`review-v0.4.1.md`）で出した要望が入ったので、使い捨てのファイルで確かめた。以降は普段の作業で使いながら、ここに追記する。

## 結論

要望 4 つ（BEFORE / AFTER、行の一部だけを書いたときのヒントで BEFORE / AFTER を案内、未知のオプションは 1 行の usage、ヘルプの Tips）は、どれも期待どおりに動いた。直してほしいのは、2 行にまたがる BEFORE / AFTER の診断だけ（下の 1）。

## 試したこと（すべて期待どおり）

- **BEFORE で行の一部を指定**: Markdown の長い 1 行（`- 対象から先に外す（後回し）: …`）の先頭だけを書いて、その前に 1 行を挿入。NEW のバッククォートと `${y}` もそのまま入った。v0.4.1 の場面 2・9 の書き方がそのまま通る。
- **AFTER で、改行のない最終行の後ろに挿入**: 足した行が最終行になり、改行なしの状態は保たれた。
- **CRLF のファイルに AFTER**: 足した行も `\r\n` になった。
- **アンカーが 2 行に当たる（count なし）**: `expected 1 match, found 2` と、当たった行番号と行の全文が出て、何も書かれない（終了コード 1）。
- **`AFTER count=2`**: 2 行のそれぞれの後ろに入り、`at_lines=3,5`。
- **アンカーが空、NEW が空**: どちらも入力の誤りとして終了コード 2（「the AFTER text is empty」「nothing to insert」）。メッセージが分かりやすい。
- **OLD に行の一部だけを書く**: ヒントの最後に「足すだけなら BEFORE/AFTER（行の一部でよい）」が付いた。
- **同じファイルで AFTER のあとに OLD**: 2 つめの OLD は、1 つめで挿入した行に当たった（順に適用される）。`edits=2`。
- **`-n`（dry run）**: `at_lines` を出し、何も書かない。
- **未知のオプション（`-X`）**: 1 行の usage と `--help` の案内だけで、終了コード 2。
- **`--help` の Tips**: `<<'EOF'` の引用符と `&&` の 2 つが入った。

## 気づいたこと・要望

1. **2 行のアンカーの診断が分かりにくい**。BEFORE / AFTER に 2 行を書くと（`b long` と `c`）、`"after" not found` / `no similar text found` になる。ヘルプは「the line that contains the text」と書いているので 1 行のアンカーが前提だと分かるが、実際には 2 行とも存在する行なので、「似たものがない」と言われると戸惑う。
   - 案: 入力の読み取りの時点で「BEFORE/AFTER の text は 1 行だけ（2 行あった）」と終了コード 2 で止める。複数行のアンカーを許す必要はないと思う（場所を決めるには 1 行で足りる。足りないときは count か、より長い一部を書けばよい）。
2. **JSON には before / after がない**（`unknown field after`。フィールドの一覧が出るので、すぐ分かる）。BEFORE / AFTER は行の一部を書けるので、JSON に逃げる理由がもともとないため、困らない。ヘルプの JSON の節に「BEFORE/AFTER は区切り形式だけ」と一言あると、探さずに済む。
3. アンカーが複数に当たったときのヒント（`add surrounding text to "after" so that it matches once`）は、BEFORE / AFTER なら「全部に入れたいなら count=N」も添えるとよい。OLD と違って、複数の行に同じものを足したい場面（例: 各セクションの見出しの後ろ）がありうる。
